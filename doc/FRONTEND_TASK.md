## 当前目标

阶段 8：Settings 功能接入与项目交付整理已完成代码级验收。当前任务书保留为交接记录，后续进入新阶段时再由文档会话更新。

## 当前任务

### 任务 1：Settings 功能状态梳理

- 检查 `/Settings` 页面所有区块和按钮。
- 对“邮箱”、“模型配置”、“RAG 参数”、“删除账号/删除数据”等功能逐项标记：
  - 已接后端，可以真实保存。
  - 需要后端接口，本阶段实现。
  - 暂不实现，只显示说明或禁用态。
- 不允许出现“点击保存成功但后端没有保存”的假功能。

### 任务 2：邮箱/账号资料接入

- 如果后端提供用户资料接口，前端通过 `src/api/` axios wrapper 读取和保存。
- 邮箱如果只是资料字段，UI 文案写“邮箱”；如果需要验证邮箱，本阶段先不做验证流程，必须明确说明。
- 保存失败要有 toast 或错误提示。

### 任务 3：模型配置接入

- 前端不能展示真实 API key 明文。
- 如果后端只支持环境变量级模型配置，Settings 页面应展示“由后端环境变量管理”，不要做用户级保存。
- 如果本阶段实现用户级模型配置，必须按 `doc/API.md` 的接口读取/保存，并对密钥做脱敏展示。

### 任务 4：RAG 参数接入

- 明确 RAG 参数是前端本地偏好、用户级配置，还是知识库级配置。
- 如果后端未使用这些参数，不要做成“已生效”的保存项。
- 如果后端实现用户级 RAG 参数，前端通过 API wrapper 保存，并在 Chat 请求或后端配置中真正生效。

### 任务 5：删除账号/删除数据

- 删除账号或删除当前用户数据必须有二次确认。
- UI 文案要明确会删除哪些数据：知识库、文档、chunks、会话、消息、引用来源等。
- 如果后端未实现，不要保留可点击的假删除按钮。

### 任务 6：交付整理配合

- 配合 README 中的演示流程，确保 Settings 页面不会出现误导性功能。
- 如新增 API，更新前端 API wrapper、类型和错误处理。

## 开发规则

- 先读 `AGENTS.md`、`doc/STAGE_PLAN.md`、`doc/PROJECT.md`、`doc/API.md` 和本文件。
- 使用 `src/api/http.ts` 的 axios 实例。
- 新增或调整接口调用时，把请求/响应类型和 API wrapper 放在 `src/api/` 对应文件里。
- 不使用直接 `fetch`。
- 不在组件里直接访问 `localStorage`。
- 需要跨页面共享或持久化的状态才使用 Zustand；纯 UI 状态用组件内 `useState`。
- UI 使用 shadcn/radix-sera 组件、Lucide 图标和现有 Tailwind 风格。
- 如涉及 UI 修改，参考 `$ui-ux-pro-max`：专业 SaaS/知识库工具风格，避免营销式页面、嵌套卡片、文字溢出、过度装饰、hover 布局位移。
- 页面文件保持轻量，复杂 UI 拆到 `src/components/<feature>/`。
- 不为了视觉整理改动后端接口契约；如果确实需要新接口，先记录需求并让文档会话同步 `doc/API.md` 后再开发。
- 除非用户明确要求使用 `@chrome`、`@浏览器`、Playwright、截图或其他浏览器工具做验收，否则不要主动打开浏览器做 UI/视觉验收；默认只跑 `pnpm build`、目标 ESLint、类型检查等代码级验证，并把浏览器验收步骤交给用户。

## 验收标准

- `pnpm build` 通过。
- 目标文件 ESLint 通过；如果全量 `pnpm lint` 有历史问题，要明确列出不属于本次改动的问题。
- `/Settings` 不再出现未说明状态的假保存、假模型配置、假 RAG 参数或假删除功能。
- 已实现的 Settings 功能能真实读取/保存后端数据。
- 暂不实现的 Settings 功能有禁用态或明确说明。
- 新增请求都走 `src/api/` 的 axios wrapper，不新增直接 `fetch`。
- 不新增组件级 `localStorage`。
